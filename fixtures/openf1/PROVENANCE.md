# OpenF1 fixture provenance

Recorded historical fixture captures from the public, free, **unauthenticated** OpenF1 API
(`https://api.openf1.org/v1/`), for the MVP's historical source fixtures.

- **Recording date (UTC):** 2026-10-10 (first request `2026-10-10T22:29:12Z`, last `2026-10-10T22:29:21Z`).
- **Authentication:** none. No token, no `Authorization` header, no cookies, no subscription, no account.
  Free-tier historical reads only.
- **HTTP client:** purpose-built throwaway recorder kept outside the repository (in `/tmp`), using a plain
  HTTP client with `trust_env=False`, `follow_redirects=False` and a bounded timeout. The project's own
  HTTP client was not used, and no project file was modified to make the recording possible.
- **Methods:** `GET` only, host `api.openf1.org` only. **Total requests: 8** (each returned HTTP 200 on the
  first attempt; no retries were needed and none were performed).
- **Measured pacing:** at least 0.4 s between requests (sleep 0.5 s), observed inter-request gaps
  `1.610, 0.840, 0.776, 1.142, 2.586, 0.764, 0.764` s; wall-clock window 8.481 s for all 8 requests,
  minimum observed gap 0.764 s. This stays inside the documented free-tier limits, stated as the two
  different kinds of bound they are: **8 requests** is well inside the **30 per minute** count, and the
  observed maximum instantaneous rate is well inside **3 per second**.

## What this recording is — and is not

Reading a documented URL path is **not** the same as observing a response shape. This recording is what
turns a documented path into a recorded fact: it captures, at one point in time, the exact bytes the
unauthenticated free tier returned for these query strings, with hashes and counts.

It says nothing about live, real-time, authenticated or rate-limit-exempt behaviour, and it makes no claim
about whether the same shapes hold for other sessions, seasons or times. The upstream data for a past
session can be revised after this snapshot: the eight families below capture the bytes seen on
**2026-10-10**, and the three championship and session-result files added afterwards capture the bytes seen
on **2026-10-12** (see the section at the end). Neither capture is an evergreen truth.

## Total size and the size gate

**Total recorded size: 3,599,681 bytes (3.60 MB, 3.43 MiB)** across the eight fixtures.

The pre-agreed size gate (stop and report if any single family exceeds roughly 2 MB, or the total exceeds
roughly 12 MB) fired on one family:

| Family | Bytes | MB | MiB |
| --- | --- | --- | --- |
| **intervals** | **2,965,644** | **2.97** | **2.83** |

`intervals.json` was therefore **measured at 2,965,644 bytes / 21,041 records**, above the ~2 MB family
gate. **The maintainer accepted it whole.** The final artifact set is complete as recorded; the final total
size is **3,599,681 bytes (3.60 MB, 3.43 MiB)** across the eight fixtures, inside the ~12 MB ceiling. The
other seven families together are 634,037 bytes (0.63 MB).

Accepted whole, and why the alternatives were declined:

- A `date>=2024-10-20T19:00:00` bound was rejected as nearly pointless: only **1 of 21,041** intervals rows
  predates the session's stated `date_start`, so the bound would have removed a single row and saved roughly
  140 bytes — a change that looks like a mitigation while doing nothing.
- Per-driver bounding (`driver_number=`) was rejected because it would drop part of the grid; a replay
  regression corpus needs the whole field, not a subset.
- Withholding the family was rejected because intervals are within F04's stated scope and would be lost.
- A single ~2.97 MB text file is acceptable for this repository's regression corpus: it is a point-in-time
  artifact, not a growing log.

`intervals.json` holds 21,041 rows for 20 distinct drivers over the race window, i.e. a per-driver gap sample
roughly every 6 seconds of the race.

**Nothing was trimmed, sampled, reshaped or replaced.** All eight files are stored exactly as received
(verbatim bytes), and the size gate is now closed.

### Deliberately excluded: `intervals`

`intervals` was **deliberately not fetched**, and the omission is declared rather than left as a silent gap.
Two measured reasons, both from the existing corpus and from the code that reads it:

1. **Nothing consumes it.** The collector derives **no event** from `intervals`, and

2. **It is the single largest family.** The only measured instance is session 9617's

   fetched**, so its size is **not measured** and no number is invented for it.

`team_radio`, `overtakes` and the other unread paths. The ten families above are the declared loaded
